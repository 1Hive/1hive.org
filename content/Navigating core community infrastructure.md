1Hive is not a single app. It is a set of social, economic, and technical systems for governing Honey and directing it toward public goods.

This page is a practical map of that infrastructure. Use it to find where proposals happen, where disputes are handled, where contributors coordinate, and where the community experiments with new allocation mechanisms.

**This is a reference map, not a live status report.** Links identify documented deployments and spaces. They do not confirm an active funding program, available balance, current rule set, or working interface. Verify those details at the source before making a commitment or transaction.

## Start here

For website, documentation, and tooling contributions, start with [[How you can contribute]] and the [repository contribution guide](https://1hive.org/CONTRIBUTING.md). A small, reversible fix can use a normal pull request. The [[Improvement proposals|working-draft improvement process]] helps with changes that need a longer-lived plan.

For work that needs shared funding or a governance decision:

1. Discuss an idea in Discord or the Forum.
2. Verify the relevant deployment's current rules, eligibility, and available funds.
3. Prepare a clear proposal with scope, budget, recipient, risks, and expected evidence, then use the applicable governance process.
4. Respond to questions, challenges, and requested changes.
5. Deliver the work and make the result easy for others to inspect.

The tools below support different parts of that path.

## Common Pool governance

- [Gardens v1 deployment](https://gardens.1hive.org/#/xdai/garden/0x8ccbeab14b5ac4a431fffc39f4bec4089020a155)

Gardens v1 is the documented deployment for 1Hive Common Pool proposals and Honey governance actions.

It is a starting point for researching how to:

- request Honey from the Common Pool,
- vote on proposals,
- review active or historical funding requests,
- participate in community-wide Honey governance,
- challenge proposals that violate shared rules,
- review the 1Hive covenant.

Check the current covenant, submission requirements, proposal state, and execution conditions before taking action. Do not infer that funds are available from the existence of the interface.

## Gardens v2 experiments

- [Gardens v2 community](https://app.gardens.fund/gardens/100/0x71850b7e9ee3f13ab46d67167341e4bdc905eef9/0xe2396fe2169ca026962971d3b2e373ba925b6257)

The Gardens v2 community deployment is a reference for experiments with more modular and continuous allocation processes.

The wiki records pools for contributor-support signaling, citizenship, liquidity, and council membership. See [[Curating community contributions]] for individual links. Their current activity, budgets, rules, and execution arrangements need to be verified; a listed pool does not imply an active reward program.

Use a pool only after checking that its current purpose and terms fit the proposal or signal. These experiments explore smaller and more specialized decisions, but their existence does not remove the need to verify who can execute a result.

## Dispute resolution

- [Celeste deployment](https://celeste.1hive.org/#/dashboard)
- [Celeste documentation](https://1hive.gitbook.io/celeste)

Celeste is the dispute-resolution system documented for 1Hive governance.

Shared resource allocation needs rules and ways to resolve disagreements about them. Celeste's documented design uses staking, challenges, evidence, and juror decisions. Check its current deployment and the specific governance integration before relying on a challenge or juror workflow.

Use Celeste-related resources to research how to:

- understand proposal challenges,
- review disputes and evidence,
- stake Honey as a juror,
- enforce governance rules,
- learn how the covenant is backed by dispute resolution.

## Discussion and coordination

- [1Hive Forum](https://forum.1hive.org)
- [1Hive Discord](https://discord.gg/1hive)
- [1Hive GitHub](https://github.com/1Hive)

Use the Forum for proposal drafts, budgets, governance reasoning, and public records. Use Discord for live coordination and contributor discovery. Use GitHub for code, documentation, issues, and technical review.

A useful rule of thumb:

- If it needs quick discussion, use Discord.
- If it needs durable public reasoning, use the Forum.
- If it needs maintained technical work, use GitHub.
- If it moves Honey, verify the applicable governance and execution process first.
- If it involves a rule violation or challenge, check the relevant rules and dispute-resolution integration.

## How the system fits together

Each tool does one part of the work:

- **Honey** coordinates value.
- **Gardens v1** allocates Common Pool resources.
- **Gardens v2** supports focused allocation experiments.
- **Celeste** provides dispute resolution and rule enforcement.
- **Forum and Discord** help people form proposals and coordinate work.
- **GitHub** makes technical contributions inspectable and reusable.

The point of this infrastructure is to make it possible for a global community to fund public goods, steward shared resources, and keep improving the systems it depends on. Site and contributor-process improvements can proceed independently of research into protocol changes. The [[Improvement proposals|working-draft proposal process]] does not change any of the deployments or rules listed here.
